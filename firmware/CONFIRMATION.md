# 设备确认协议草案（未部署，不可用于生产）

此文描述 `202610290002_device_confirmation.sql` 中的**服务端基础**，不是已可使用的端到端协议。现有网页、ESP32 固件和真实 Supabase 尚未集成。所有请求需使用 HTTPS；设备密钥只能放在 POST 请求体内，不能放在 URL、日志或 Git。

1. 网页使用独立的请求 UUID 创建确认请求。设备通过 `device_status` 发现该请求。存在未完成请求时不能改绑。
2. 设备必须持久化冻结状态，暂停新批次提交，并先排空**所有**先前未上传的计数，然后报告持久化的绑定、epoch 和累计值。服务端只验证这个 epoch 的累计值已接收；它无法观察其他未知的设备本地队列，因此必须依靠正确实现并验证的设备端排空协议。
3. 服务端冻结计数快照，签发两秒租约和一次性续约 nonce。相同的冻结请求重试不会延长租约；续约成功会更换 nonce，旧 nonce 不能再次续约。续约回应丢失时，设备可以认证后查询确认状态以找回最新 nonce。过期租约不能复活，必须取消并重新发起。
4. 设备按约定保持冻结并约每秒续约；网页只有在快照就绪且租约未过期时才能提交确认。服务端提交时锁住设备、快照、设备草稿与生产单，重新检查租约和草稿，并在一个事务内封顶累计、记录历史和清零设备草稿。重复提交返回同一结果；失败不应清除草稿。
5. 冻结期间操作人员应暂停按键。正式固件仍须定义并持久化误按处理：冻结快照之后的按键不能被静默丢弃，也不能混入已确认快照，应可靠保留到下一批或使本次确认安全取消。断电重启、租约过期、撤销/改绑及响应丢失时，都必须证明恢复不会遗漏或重复累计。

两秒租约只是故障检测近似值，不能百分之百证明设备在确认瞬间仍在线。短期网络中断、时钟/调度延迟、重复包、请求重放和运行时间跨越租约边界都需测试；设备本地应采用单调时钟和保守超时，不能仅相信本地墙钟。

PR1 的手动输入与确认函数没有修改。设备端联网、实时界面、下载页面、跨批次持久化、Supabase Realtime、真实并发测试、密钥安全配置、存储寿命与真机测试仍未完成，不要部署这些迁移或烧录测试代码。

## 草稿阶段新增的设备持久状态

`DurableCounter` 目前保存生产单 UUID、服务端绑定 UUID、绑定递增版本、计数 epoch、累计值、已确认值和冻结请求 UUID。服务端绑定请求在设备行锁内分配递增版本；设备应拒绝较旧版本，并在本地待传计数排空后才切换。尚未绑定、存储异常或冻结期间，不允许调用方上传新增计数。

收到冻结请求时，设备端应先把全部旧计数上传并确认，再持久化冻结记录。冻结后误按的数值保存在同一设备快照中，但不得上传或继续发送冻结续约；设备应尽快使用设备认证的 `device_confirmation_abort` 请求取消；该请求和网页确认由服务端同一把设备锁串行化。若服务器先完成确认，这些数值仍保留在下一批。断电重启后依旧保持冻结；只有通过认证的服务器明确返回完成、取消或已过期，才能解除本地冻结并上传后续数值。**这些是组件能力和集成要求，网络调用、取消流程、设备提示和网页尚未完成。**

设备必须为当前绑定/epoch 先成功发送至少一次累计值（包括零），服务端才能验证冻结快照。设备仍需对请求重试、后台同步、重复按键与失电进行端到端验证。冻结期间若出现误按，设备取消请求与网页确认仍可能竞速；不得把两秒租约解释为严格的即时在线证明。

当前持久快照格式已从未发布的草稿版本 1 改为版本 2；旧测试数据会被拒绝而不会被自动清除。如果曾经烧录过任何草稿测试代码，**不要清空 NVS 或重新烧录以试图修复**，应先备份并确认未同步数据；正式迁移与恢复流程仍未实现。

## 设备同步调度核心（未接入网络）

`SyncPlanner.h` 只生成待发送命令并消费带 ticket 的模拟响应，不包含 Wi-Fi、TLS、JSON 解析或 HTTP 实现。它会先上传旧绑定中待同步的累计值再应用新绑定；首次连接会登记零计数 epoch；请求失败后不提前清除本地计数。冻结请求响应不确定时先查询服务器；冻结后误按会停止续约并请求取消，若确认已经完成则保留误按数供下一批上传。设备重启后仍依照持久冻结记录恢复。过期、取消和完成都需要来自已认证的服务端响应，不能仅凭本地超时解除冻结。

此核心要求**单线程串行**访问计数器与调度器。未来的网络实现必须异步、验证服务器 TLS 证书、限制请求时长，并通过线程安全队列将响应送回计数线程，不能在网络阻塞时停止 GPIO 采样。设备凭据、Wi-Fi 配置、设备状态提示、网络层与真实联调都尚未实现。轮询与续约使用设备单调毫秒计数；200 毫秒最小发送间隔、500 毫秒状态轮询和约 750 毫秒续约只是调度目标，网络慢或断线时不构成延迟保证。存储错误、异常服务器确认或状态不一致会停止调度并要求安全恢复，不能自动清空本地状态。

`RpcCodec.h` 和 `RpcWorker.h` 是未联网的编码、解码及传输接口基础，不会自动发送网络请求。未来接线时必须先检查 HTTP 状态和 TLS，再将解码成功的响应按 ticket 送回 `SyncPlanner`；不能将错误响应、其他请求的响应或未认证的内容作为成功确认。密钥不会放在 RPC 路径中，传输层不得记录 POST 内容。网络任务与计数线程之间必须串行交接计数器和调度状态，不能跨线程直接并发访问。

线程交接由 `SyncController` 和 `SyncNetworkWorker` 分别在计数线程和网络线程调用，使用单条命令、单条回复的非阻塞队列。网络失败返回失败回复，不清除本地待同步数；网络工作器若无法交付结果，会保留回复等待重试，而不会重复执行请求。队列拥塞或未知 ticket 在控制侧视为故障。此组件不创建网络任务，也不保证 NVS 操作的实时性；任务生命周期和安全传输仍需实现并在硬件上测试。

## 网页确认恢复控制器（未接入界面）

`src/device-confirmation.js` 在发送设备确认请求前保存请求 UUID，响应丢失时用同一 UUID 重试；确认提交前标记可能存在未确定结果，并通过相同 barrier 查询已完成状态。取消与提交由服务端锁串行化，取消失败不清除恢复记录。记录只包含标识和结果，不含凭据；仅在服务端确认完成或取消、用户确认结果后才能清理。

控制器尚未连接现有网页，也未在真实 Supabase 上测试。它要求浏览器支持 Web Locks 和可用的 localStorage；不同设备上的并发依赖服务端锁，清除浏览器数据、存储损坏或不同浏览器的恢复流程仍需设计。iPhone/Android 实际支持及恢复体验必须验证，不能因此声称功能可用。

`202610290003_device_confirmation_recovery.sql` 增加未部署的只读查询，允许共享账号找到某设备尚未结束的确认；它不返回设备密钥或续约 nonce。控制器在没有本地记录时先检查服务器，发现未结束请求时可由操作员确认暂停后恢复，不会自动新建。若不同设备同时发起，服务端唯一约束负责阻止同时存在两个未结束请求；如果本地已保存了结果不明的请求，不能用其他请求覆盖，仍需要安全恢复。

**限制：**该查询只返回未结束请求。若确认已经完成且原浏览器的恢复记录丢失，仅凭“没有未结束请求”不能证明之前未提交；必须核对生产历史，不能自动重复确认。跨设备竞态、浏览器存储清除以及真实 Supabase 并发仍需进一步验证。

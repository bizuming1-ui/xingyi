# ESP32-S3 按键计数开发中

`include/ButtonCounter.h` 是已单独测试的按键去抖与长按计数核心，不是完整固件，不能直接烧录使用。按键连接 GPIO 4 和 GND，最终固件将使用内部上拉。按下稳定 25 ms 后加 1；保持 500 ms 后每 100 ms 加 1，释放期间不会继续重复计数。真实网络通信、设备配对、断网队列的端到端联调、确认同步握手和网页集成尚未实现；请勿将这个文件作为完整生产代码使用。

主机环境测试：`g++ -std=c++17 -Wall -Wextra -Werror tests/button_counter.cpp -o /tmp/xingyi-button-test && /tmp/xingyi-button-test`。实际开发板接线、长按、断网与断电行为尚未验证。

## 已确认的需求（后续实现前仍需验证）

- ESP32-S3-N16R8、GPIO 4 接按键另一端接 GND；2.4 GHz Wi-Fi，凭据仅在用户本地配置。
- 暂时一台设备，通过网页选择生产单；离线计数归属于发生时的原生产单，即使稍后改绑也不可转移。
- 网页手动输入维持独立，设备计数作为共享数单独显示并单独确认；设备计数确认按生产总数封顶，超出部分清空。
- 网络正常时目标 1 秒内显示；断网需要本地持久队列，目标支持至少一天（按最长 8 小时、每秒 10 次估算）。容量耗尽必须停止接受并提示。断电保存尽力而为，接受极短写入窗口丢数风险。
- 设备离线或存在未同步计数时禁止确认；确认需要同步握手并提示操作人员暂停按键。必须设计实际暂停/确认竞争的安全行为，不能仅用心跳猜测已同步。
- 下载页为独立网址。正式网页和现有数据库不能在无迁移、回归与多端测试的情况下直接改动。

## 离线存储组件（仍在开发中）

`DurableCounter.h` 定义了绑定 UUID/版本、计数累计值、已确认值与冻结状态；存储层使用两个独立快照、校验和及递增版本。冻结期间误按会留在待传计数中，重启后不会自动解冻。重传时携带累计值的设计可以支持服务端幂等处理，但对应的服务端协议已在未部署迁移中实现。存在未同步计数时组件拒绝改绑；写入或读取校验失败时停止接受计数，不能静默清零。`PreferencesCounterStorage.h` 是 Arduino Preferences/NVS 适配器，已通过主机模拟测试和 ESP32-S3 PlatformIO 组件编译，**尚未在开发板上验证**。

测试命令：`./tests/run-firmware-tests.sh`。此测试覆盖去抖、长按、计数重启恢复、重复确认、错误绑定、模拟存储故障和模拟 Preferences 接口；不证明断电原子性、闪存寿命、一天离线容量、网络交互或硬件兼容性。10 次/秒高频写入可能明显加快闪存磨损，完整方案必须经实际断电及耐久测试，必要时需要优化写入策略或增加硬件。

`tests/esp32_compile` 是专门的 PlatformIO **仅编译检查**，使用 `esp32-s3-devkitc-1`、16 MB Flash 和 QIO/OPI 内存配置编译当前组件，不能当作功能完整的固件烧录。该检查由 PR 中独立的 GitHub Actions 执行；本地如果有 PlatformIO，也可执行 `pio run --project-dir tests/esp32_compile`。编译成功只验证接口和工具链兼容，不能替代实板测试。

## 尚未部署的服务端接收基础

`supabase/migrations/202610290001_device_ingest.sql` 是独立新增的设备接收基础，不替换 PR1 表、权限或手动确认函数，也**尚未应用到线上**。它实现管理员创建设备及撤销、单设备随机密钥、绑定请求、累计值幂等接收以及独立设备草稿；旧绑定仍保留，以便离线数据归到原生产单。密钥只生成时返回，固件配置和安全配对页面尚未实现，不能用于实际设备。

后续 `202610290002_device_confirmation.sql` 新增了未部署的服务端冻结、两秒租约和原子确认基础，协议及限制见 `CONFIRMATION.md`。设备端冻结/排空握手、断电后的跨批恢复、生产单删除/归档时的处理、Realtime 推送、真实并发安全和速率限制等仍未实现；在这些内容以及真实 Supabase 与实板测试完成前，不可将迁移部署到生产。`tests/database` 使用完全隔离的 PGlite 测试迁移和 PR1 手动封顶；它不是 Supabase 并发或断网测试。

`SyncPlanner.h` 是不含网络传输的单线程调度核心；主机测试覆盖旧绑定先排空、响应丢失重试、确认冻结、误按取消、重启恢复和异常响应停机。它不代表完整固件。详见 `CONFIRMATION.md`。

## RPC 请求与回复组件（尚未联网）

`RpcCodec.h` 将同步调度命令映射到已设计的 Supabase RPC，并验证 JSON 结构、UUID、计数上限、冻结状态和续约 nonce；无效或不匹配的回复不会被当成成功。`RpcWorker.h` 使用可替换的传输接口执行编码与解码，只返回安全的状态码，并清除请求及响应缓冲区。它**不包含实际 HTTPS/Wi-Fi 传输**：未来传输层必须在独立网络任务运行、校验服务器证书和主机名、禁止重定向、限制响应大小和超时，且不得记录密钥或请求体。

RPC 组件的主机测试使用固定版本 ArduinoJson 6.21.5。下载依赖后设置 `ARDUINOJSON_INCLUDE` 指向该库的 `src` 目录，再运行 `./tests/run-rpc-tests.sh`；GitHub Actions 会核对下载包的 SHA-256。测试使用模拟响应，不证明真实 Supabase、TLS、网络任务或设备行为。

## 计数线程与网络线程交接（尚未联网）

`SyncBridge.h` 将调度器和同步 RPC 工作分离：计数线程只用非阻塞队列交接命令和结果，网络工作器在另一线程执行 RPC。`FreeRtosSyncMailbox.h` 使用两个容量为一的静态 FreeRTOS 队列，命令中不包含设备密钥。一个命令未完成时不会发出下一个；队列异常或未知 ticket 会安全停机，结果队列暂满时保留结果而不重复请求。网络失败不确认计数，计数线程仍可记录请求期间产生的按键。

这只是线程交接组件，不负责创建任务、Wi-Fi 或 HTTPS。调用方必须检查队列初始化、让队列对象和密钥在两个任务使用期间保持有效，并使用有超时的安全传输。调度器和存储仅由计数线程访问；网络线程不得直接访问它们。队列操作不等待，但 NVS 保存本身可能阻塞，实时性必须在真机测量。模拟测试和 PlatformIO 编译不证明真实双核调度、网络或掉电行为。

## HTTP 回复分帧（独立组件）

`HttpResponseDecoder.h` 增量处理 HTTP/1.1 的 `Content-Length` 或分块响应，限制响应头和正文大小，拒绝截断、冲突的分帧头和无法处理的格式。它不建立连接、不校验 TLS、不跟随重定向，也不保证超时：未来传输层必须先校验服务端证书和域名、设置总时限、拒绝 3xx，并且仅在完整解析且 HTTP 状态成功时交给 RPC 解码器。为安全起见，关闭连接定界的正文、分块扩展和非空 trailers 暂不支持；上线前需在隔离环境验证实际服务端响应是否兼容。

## 固定来源 RPC 请求（隔离测试）

`HttpRpcExchange.h` 连接 RPC 编码和 HTTP 分帧：限定单个 Supabase 项目域名、六个固定 RPC 路径和 `sb_publishable_` 公钥，拒绝密钥或域名中的头部注入，不接受 secret/service-role 密钥；请求体中的设备密钥不放入 URL。它对整个请求使用一个总时限，限制响应大小、不跟随重定向，并在完成或失败后关闭连接。模拟测试覆盖分段读写、无效域名/密钥、连接失败、超时、截断、过大响应和重定向。

**仍没有可用于设备的 TLS/Wi-Fi 通道。** `VerifiedTlsChannel` 仅规定接口：实际实现必须验证证书链、主机名和有效时间，并确保连接与读写遵守传入的时限；不能使用不安全模式。当前测试只使用模拟通道，尚未验证实际 Supabase HTTP、证书、时钟同步或真机网络。

## 随机批次编号

`RandomEpochSource.h` 将安全随机字节转成 UUID v4，随机源失败时拒绝生成编号，不使用时间或伪随机数替代。`EspWifiEntropy.h` 使用 ESP32 的硬件随机源，要求 Wi-Fi 已连接，并在读取前后检查状态；运行时还必须对 Wi-Fi 开关与随机读取使用同一生命周期锁，防止读取期间关闭或重启无线电。主机测试模拟了随机源和 Wi-Fi 状态，不能证明真机随机质量或线程调度。实际设备主程序和该锁尚未实现。

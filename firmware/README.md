# ESP32-S3 按键计数开发中

`include/ButtonCounter.h` 是已单独测试的按键去抖与长按计数核心，不是完整固件，不能直接烧录使用。按键连接 GPIO 4 和 GND，最终固件将使用内部上拉。按下稳定 25 ms 后加 1；保持 500 ms 后每 100 ms 加 1，释放期间不会继续重复计数。真实网络通信、设备配对、断网队列的端到端联调、确认同步握手和网页集成尚未实现；请勿将这个文件作为完整生产代码使用。

主机环境测试：`g++ -std=c++17 -Wall -Wextra -Werror tests/button_counter.cpp -o /tmp/xingyi-button-test && /tmp/xingyi-button-test`。实际开发板接线、长按、断网与断电行为尚未验证。

## 已确认的需求（后续实现前仍需验证）

- ESP32-S3-N16R8、GPIO 4 接按键另一端接 GND；2.4 GHz Wi-Fi，凭据仅在用户本地配置。
- 暂时一台设备，通过网页选择生产单；离线计数归属于发生时的原生产单，即使稍后改绑也不可转移。
- 网页手动输入维持独立，设备计数作为共享数单独显示并单独确认；设备计数确认按生产总数封顶，超出部分清空。
- 网络正常时目标 1 秒内显示；断网需要本地持久队列，目标支持至少一天（按最长 8 小时、每秒 10 次估算）。容量耗尽必须停止接受并提示。断电保存尽力而为，接受极短写入窗口丢数风险。
- 设备离线或存在未同步计数时禁止确认；确认需要同步握手并提示操作人员暂停按键。必须设计实际暂停/确认竞争的安全行为，不能仅用心跳猜测已同步。
- 下载页为独立网址。正式网页和现有数据库不能在无迁移、回归与多端测试的情况下直接改动。

## 离线存储组件（仍在开发中）

`DurableCounter.h` 定义了绑定 UUID/版本、计数累计值、已确认值与冻结状态；存储层使用两个独立快照、校验和及递增版本。冻结期间误按会留在待传计数中，重启后不会自动解冻。重传时携带累计值的设计可以支持服务端幂等处理，但对应的服务端协议已在未部署迁移中实现。存在未同步计数时组件拒绝改绑；写入或读取校验失败时停止接受计数，不能静默清零。`PreferencesCounterStorage.h` 是 Arduino Preferences/NVS 适配器，已通过主机模拟测试和 ESP32-S3 PlatformIO 组件编译，**尚未在开发板上验证**。

测试命令：`./tests/run-firmware-tests.sh`。此测试覆盖去抖、长按、计数重启恢复、重复确认、错误绑定、模拟存储故障和模拟 Preferences 接口；不证明断电原子性、闪存寿命、一天离线容量、网络交互或硬件兼容性。10 次/秒高频写入可能明显加快闪存磨损，完整方案必须经实际断电及耐久测试，必要时需要优化写入策略或增加硬件。

`tests/esp32_compile` 是专门的 PlatformIO **仅编译检查**，使用 `esp32-s3-devkitc-1`、16 MB Flash 和 QIO/OPI 内存配置编译当前组件，不能当作功能完整的固件烧录。该检查由 PR 中独立的 GitHub Actions 执行；本地如果有 PlatformIO，也可执行 `pio run --project-dir tests/esp32_compile`。编译成功只验证接口和工具链兼容，不能替代实板测试。

## 尚未部署的服务端接收基础

`supabase/migrations/202610290001_device_ingest.sql` 是独立新增的设备接收基础，不替换 PR1 表、权限或手动确认函数，也**尚未应用到线上**。它实现管理员创建设备及撤销、单设备随机密钥、绑定请求、累计值幂等接收以及独立设备草稿；旧绑定仍保留，以便离线数据归到原生产单。密钥只生成时返回，固件配置和安全配对页面尚未实现，不能用于实际设备。

后续 `202610290002_device_confirmation.sql` 新增了未部署的服务端冻结、两秒租约和原子确认基础，协议及限制见 `CONFIRMATION.md`。设备端冻结/排空握手、断电后的跨批恢复、生产单删除/归档时的处理、Realtime 推送、真实并发安全和速率限制等仍未实现；在这些内容以及真实 Supabase 与实板测试完成前，不可将迁移部署到生产。`tests/database` 使用完全隔离的 PGlite 测试迁移和 PR1 手动封顶；它不是 Supabase 并发或断网测试。

`SyncPlanner.h` 是不含网络传输的单线程调度核心；主机测试覆盖旧绑定先排空、响应丢失重试、确认冻结、误按取消、重启恢复和异常响应停机。它不代表完整固件。详见 `CONFIRMATION.md`。

## RPC 请求与回复组件（尚未联网）

`RpcCodec.h` 将同步调度命令映射到已设计的 Supabase RPC，并验证 JSON 结构、UUID、计数上限、冻结状态和续约 nonce；无效或不匹配的回复不会被当成成功。`RpcWorker.h` 使用可替换的传输接口执行编码与解码，只返回安全的状态码，并清除请求及响应缓冲区。它**不包含实际 HTTPS/Wi-Fi 传输**：未来传输层必须在独立网络任务运行、校验服务器证书和主机名、禁止重定向、限制响应大小和超时，且不得记录密钥或请求体。

RPC 组件的主机测试使用固定版本 ArduinoJson 6.21.5。下载依赖后设置 `ARDUINOJSON_INCLUDE` 指向该库的 `src` 目录，再运行 `./tests/run-rpc-tests.sh`；GitHub Actions 会核对下载包的 SHA-256。测试使用模拟响应，不证明真实 Supabase、TLS、网络任务或设备行为。

## 计数线程与网络线程交接（尚未联网）

`SyncBridge.h` 将调度器和同步 RPC 工作分离：计数线程只用非阻塞队列交接命令和结果，网络工作器在另一线程执行 RPC。`FreeRtosSyncMailbox.h` 使用两个容量为一的静态 FreeRTOS 队列，命令中不包含设备密钥。一个命令未完成时不会发出下一个；队列异常或未知 ticket 会安全停机，结果队列暂满时保留结果而不重复请求。网络失败不确认计数，计数线程仍可记录请求期间产生的按键。

这只是线程交接组件，不负责创建任务、Wi-Fi 或 HTTPS。调用方必须检查队列初始化、让队列对象和密钥在两个任务使用期间保持有效，并使用有超时的安全传输。调度器和存储仅由计数线程访问；网络线程不得直接访问它们。队列操作不等待，但 NVS 保存本身可能阻塞，实时性必须在真机测量。模拟测试和 PlatformIO 编译不证明真实双核调度、网络或掉电行为。

## HTTP 回复分帧（独立组件）

`HttpResponseDecoder.h` 增量处理 HTTP/1.1 的 `Content-Length` 或分块响应，限制响应头和正文大小，拒绝截断、冲突的分帧头和无法处理的格式。它不建立连接、不校验 TLS、不跟随重定向，也不保证超时：未来传输层必须先校验服务端证书和域名、设置总时限、拒绝 3xx，并且仅在完整解析且 HTTP 状态成功时交给 RPC 解码器。为安全起见，关闭连接定界的正文、分块扩展和非空 trailers 暂不支持；上线前需在隔离环境验证实际服务端响应是否兼容。

## 固定来源 RPC 请求（隔离测试）

`HttpRpcExchange.h` 连接 RPC 编码和 HTTP 分帧：限定单个 Supabase 项目域名、六个固定 RPC 路径和 `sb_publishable_` 公钥，拒绝密钥或域名中的头部注入，不接受 secret/service-role 密钥；请求体中的设备密钥不放入 URL。它对整个请求使用一个总时限，限制响应大小、不跟随重定向，并在完成或失败后关闭连接。模拟测试覆盖分段读写、无效域名/密钥、连接失败、超时、截断、过大响应和重定向。

**尚没有可投入设备使用的完整网络通道。** `VerifiedTlsChannel` 规定接口；后续章节中的 `MbedTlsChannel` 已在本地测试接入证书、域名及日期验证，但仍未验证实际 Supabase HTTP、生产信任配置、时钟同步、Wi-Fi 生命周期或真机网络。不能使用不安全模式。

## 随机批次编号

`RandomEpochSource.h` 将安全随机字节转成 UUID v4，随机源失败时拒绝生成编号，不使用时间或伪随机数替代。`EspWifiEntropy.h` 使用 ESP32 的硬件随机源，要求 Wi-Fi 已连接，并在读取前后检查状态；运行时还必须对 Wi-Fi 开关与随机读取使用同一生命周期锁，防止读取期间关闭或重启无线电。主机测试模拟了随机源和 Wi-Fi 状态，不能证明真机随机质量或线程调度。实际设备主程序和该锁尚未实现。

## Wi-Fi 连接管理组件

`WifiSupervisor.h` 和 `EspWifiStation.h` 为 ESP32 提供连接尝试、断线退避和重试策略，检查 SSID/密码长度，且不会主动把 Wi-Fi 凭据写入设备持久存储。连接操作须在网络任务运行，不能放在 GPIO 采样循环；调用方必须保证 Wi-Fi 启停与硬件随机数读取互斥，也不得在 TLS 请求进行中重置 Wi-Fi。断线不会把待同步数当成已确认。

这些组件尚未接入设备主程序；测试使用模拟 Wi-Fi。真实连接、信号故障、任务锁、证书校验和网络延迟都还需要实际设备验证。

## 按键与持久计数衔接组件

`DeviceInput.h` 将去抖和长按增量交给持久计数器，并区分成功保存、未绑定、需要松开按键、容量已满和存储故障。未绑定时不接受按键；若按键在绑定前开始按下，必须松开并稳定后才能重新计数。冻结时的误按仍按既有协议持久保存为后续计数。故障与容量耗尽不会被当作成功。

该组件只返回状态，尚无实际指示灯或网页提示，也尚未接入设备主程序。`accepted` 表示本地持久化成功，不表示服务器已同步；NVS 写入耗时、断电安全和按键采样频率仍须实板验证。

## 异步 DNS 组件（本地 HTTPS 组合测试）

`AsyncDns.h` 和 `EspAsyncDnsBackend.h` 将 IPv4 解析安排到 lwIP TCP/IP 线程，使用非阻塞排队；超时只停止等待，迟到的回调仍保留原槽位，直到完成后才可复用。最多四个未结束请求，槽位耗尽时安全拒绝；如果底层始终不回调，槽位可能长期占用，不能擅自清除或复用。解析器、后端与请求内存必须比所有回调活得更久，且计时与调用只由网络任务管理。

DNS 结果不可信，不能替代 TLS 证书链及**原始主机名**校验。该组件已在本地组合测试连接到 TLS；直接把主机名再次交给 ESP-IDF 的同步解析接口仍可能重新产生阻塞。主机模拟和编译不证明真实 DNS、线程调度或超时表现，仍须真机测试。

## 非阻塞 TCP 基础（尚无 TLS）

`NonblockingTcp.h` 与 `EspTcpOps.h` 使用已解析的 IPv4 地址进行非阻塞连接、读写和连接超时检查，不重复查询 DNS。连接状态由网络任务轮询，超时或错误时关闭套接字；连接超时与设备计数线程隔离。主机测试包括状态模拟和本地回环，但回环只发送测试字节。

**这不是安全通信实现，不得用它明文发送设备凭据或生产数据。** 后续仍需 TLS、可信根证书与原始主机名校验、证书时间、整体请求时限以及真实设备测试；在这些完成之前不能投入生产。连接超时不是整个 HTTPS 请求超时。

## DNS 与 TCP 连接组合（尚无 TLS）

`ResolvedTcpConnect.h` 将异步 DNS 和数值 IPv4 TCP 连接组合起来，在同一个连接建立时限内依次轮询两者，并保留原始主机名供未来 TLS 验证。超时或关闭时不会复用仍等待 DNS 回调的槽位；DNS 失败、TCP 失败和槽位耗尽均不视为连接成功。调用必须由网络任务独占，DNS 后端及解析器必须活得比任何迟到回调更久。

此时限仅覆盖 DNS 和 TCP 建连，**不覆盖 TLS 握手或 HTTP 请求**。组件没有加密或身份验证，不能发送密钥和生产数据；整体 HTTPS 时限、可信 CA、原始域名、证书有效时间和真机表现仍需实现与验证。

## mbedTLS 会话核心（本地 TLS 测试，尚未接入生产）

`MbedTlsSession.h` 在已连接的非阻塞 TCP 上执行 TLS 握手，要求 TLS 1.2 或更高版本、可信 CA 链、原始 Supabase 域名以及证书有效时间检查。未建立可信时间、证书日期或主机名验证失败时拒绝会话；握手通过前不允许应用层写入。此组件不内置生产 CA 或同步时间服务，调用方传入的“时间可信”标志必须基于实际可靠的时间建立机制，不能仅凭设备时间看似合理就置为真。发送遇到 `WantIo` 时需用原来的缓冲区和长度重试。

主机测试使用临时本地 CA、证书和 TLS 服务器，检查有效握手、加密 HTTP、错误 CA、错误主机名、过期证书及未建立可信时间的拒绝；不连接 Supabase，也不使用真实凭据。`MBEDTLS_DIR` 指向已编译的 mbedTLS 2.28.10，`ARDUINOJSON_INCLUDE` 指向 ArduinoJson 6.21.5 的 src 后运行 `python3 tests/run-mbedtls-tests.py`。GitHub CI 固定源码版本和 SHA-256，ESP32-S3 工作流额外编译组件。

**会话核心本身不是完整 HTTPS 通道或生产固件。** 后续章节的组合组件已绑定 DNS 和 TLS 域名并增加协作式时限；仍须提供可信时钟和可维护的 CA、实际任务调度，并验证 ESP 端熵、握手期间 CPU 耗时、重试/关闭及真实网络行为。mbedTLS 加密计算可能占用 CPU，非阻塞套接字不意味着单次握手调用有严格执行时间上限。

## DNS、TCP 和 TLS 建连组合（本地验证）

`VerifiedConnect.h` 串联异步 DNS、TCP 和 mbedTLS 握手，始终使用 DNS 请求的原始主机名验证证书，且在同一单调时钟时限内轮询建连与握手；超时或失败会关闭连接，并保留尚未返回的 DNS 回调槽位。组件检查 TLS 和 TCP 是否使用同一底层连接。测试使用模拟 DNS、本地 TLS 服务器和临时证书，覆盖成功握手、错误域名、DNS 失败、迟到回调、时钟回绕和握手阶段超时。

这是协作式时限：每次操作前后检查，但不能抢占正在执行的加密计算。它只覆盖**连接建立**，不包含后续 HTTP 读写的总时限，也不负责建立可信时间或生产 CA。当前仍未接入真实 Supabase、设备任务或生产固件；不得将本地测试通过等同于设备已安全联网。

**ESP32-S3 SDK 日期验证：** Arduino-ESP32 2.0.17 的 `qio_opi` 预编译 SDK 未启用 mbedTLS 内置日期检查。现在通过 mbedTLS 的验证回调逐个检查验证链中的证书（包括根证书）的 UTC 有效期，不清除其他验证错误。主机测试分别使用启用和禁用内置日期检查的 mbedTLS，覆盖过期叶证书、中间证书、根证书及尚未生效的叶证书；尚未完成 ESP32 真机验证。不能仅在应用编译参数里定义宏来更改预编译库。可信时间来源仍是独立的未解决问题。


## 本地 HTTPS RPC 组件联测

`MbedTlsChannel.h` 在专用网络任务中将经过域名、证书链和日期校验的连接适配到 `HttpRpcExchange`；正常请求必须提供有效的 `TrustedTimeWindow`，验证证书对整个时间误差区间均有效；对连接和各次读写使用超时并在等待网络时让出执行。整个 HTTP 请求继续使用 `HttpRpcExchange` 的总时限。时间可信状态在连接和读写中检查，失效时关闭连接。该阻塞式适配器不能在按键计数任务调用；TLS 计算及平台调度不能被协作式时限强制抢占。

本地测试用临时 CA、证书、DNS 模拟和 TLS 服务器，贯通固件 RPC 编码、HTTPS 请求及响应解码，并覆盖域名/CA 错误、时间失信和响应超时。它不连接真实 Supabase，不验证真机、不提供生产 CA 或可信时间源，也不是可烧录固件。调用方须保证 Wi-Fi 生命周期、CA 内存、DNS 后端和会话对象的并发安全与寿命；不得把普通未经认证的 SNTP 自动标记为可信时间。

## 可信时间证明原型（隔离测试，尚未部署）

`TimeProof.h` 与未部署的 `202610290004_device_time_proof.sql` 实现一次性挑战证明：设备使用安全随机数生成 256 位 nonce；服务器对设备编号、nonce 和服务器秒数计算 HMAC-SHA256；设备用自己的密钥派生值验证，校验设备编号、时限、时间范围和标签，并在成功或失败后销毁 nonce 和派生密钥。响应不得重放；设备密钥和派生值不得放入请求、URL 或日志。服务器时间必须本身可信；服务端持有派生值，应作为敏感数据保护。端点需要在上线前设置网关限流并审查设备 ID 枚举和资源消耗。

隔离数据库与实际 C++ 验证器联测覆盖真实签名、错误设备/密钥/nonce、篡改、过期请求、时钟计数回绕及撤销设备。测试中的 nonce 和密钥仅为固定模拟数据，不得用于设备。

**这仍不是可用的可信时钟。** 后续章节的时间专用启动传输已通过本地测试；仍须考虑签名时间按秒取整、最多五秒往返造成的不确定区间、时间源漂移、重启和断网后的可信期，并用真实设备验证 TLS 区间校验和可信时间的生命周期。未经认证的普通 SNTP 不能直接标记为可信。迁移未部署，所有测试都是隔离环境，不能因此声称设备能安全联网。

`TimeProofCodec.h` 将活动挑战编码为仅包含设备 ID 与 nonce 的请求，严格解析时间证明回复；拒绝重复字段、额外字段、非字符串值、转义字符、截断和尾随数据，任何错误都会废弃该 nonce。隔离测试将真实数据库返回的证明交给固件解析及 HMAC 验证；该数据格式已接入后述时间专用启动传输，但尚未连接实际设备时钟设置。

## 仅用于时间证明的启动连接（本地测试，尚未部署）

`TimeBootstrapExchange.h` 将时间挑战与 DNS、TCP、TLS 和 HTTP 分帧连接起来。由于启动时尚无可信时间，该连接**只忽略证书的有效期错误**，仍验证 CA、签名链和原始域名；它没有通用写入 API，只能向固定的 `device_time_proof` 路径发送设备 ID、随机 nonce 和公开 publishable key，绝不发送设备密钥或其派生值。只有收到正确 HMAC、在整体时限内完成且 nonce 匹配的证明，才返回时间；任何失败都关闭连接并销毁挑战。

本地 TLS 服务测试包括过期证书下取得有效证明、错误 CA/域名拒绝、签名篡改、错误密钥与超时；测试还检查请求只有允许的字段，并且不含模拟设备密钥。该连接不能用于正常 RPC，也不能因启动成功而跳过后续 TLS 的完整日期校验。测试只使用临时密钥与本地服务；与未部署的数据库函数分别通过隔离联测。

目前尚未将证明接入实际设备系统时钟；正常 TLS 已在本地模拟中接入误差区间校验，Wi-Fi 生命周期互斥、生产 CA 和真机联调仍未完成；时间证明端点也尚未部署或配置限流。不要烧录投入生产。由于只忽略日期的启动连接依赖证明 HMAC 阻止时间伪造，变更其固定请求、响应验证或密钥处理前必须重新做安全审查。


## 时间误差区间与失效保护（模拟测试）

`TrustedTimeWindow.h` 根据已验证证明的服务器秒数及完整请求往返时间，保守计算真实 UTC 的上下界，考虑秒数向下取整、毫秒计时量化和调用方设定的最大振荡器漂移；过期、单调时钟倒退或时钟读取失败时失效。`EspMonotonicMillis.h` 使用 ESP 启动后的 64 位单调计时；重启后必须重新获取证明。`TimeWindowSynchronizer.h` 将时间专用启动请求与该区间组件衔接，刷新失败清除旧信任。

主机测试覆盖边界、过期、计时故障和 32 位毫秒回绕，并模拟 2 万组延迟和时钟漂移；另使用本地 TLS 服务器验证证明与区间衔接。这些只是组件测试：最长可信期和最大漂移必须根据设备硬件保证确定，尚未接入实际设备系统时钟，不能据此标记生产时间可信。


## 正常 TLS 的时间区间校验（本地测试）

正常 `MbedTlsChannel` 必须使用有效的 `TrustedTimeWindow`，TLS 验证链中每张证书的有效期必须覆盖该窗口的最早和最晚可能时间；当窗口跨越证书生效或到期边界时，连接会被拒绝。若 SDK 根据未经验证的系统时钟设置日期错误标志，回调仅用已认证的时间区间重新计算日期标志，不清除域名、签名或信任链错误。时间窗口过期或失效时，连接和读写均拒绝继续。

本地测试覆盖证书边界、时间失效、错误 CA/域名；还使用模拟签名时间服务、本地 TLS 和模拟 RPC，串联时间证明、误差区间与正常 HTTPS 请求。真实时间服务、ESP32 振荡器误差、密钥配置、Wi-Fi 生命周期和生产 CA 仍需实际设备及部署验证；不能把模拟联测当作真实联网完成。

## Wi-Fi 生命周期与安全随机互斥（组件测试）

`FreeRtosRadioLifecycleLock.h` 提供静态、非等待的 FreeRTOS 互斥锁；`GuardedWifiSupervisor` 在获得同一把锁后才执行无线启停策略，锁忙时不改变状态。计数任务和网络任务各自使用独立的 `GuardedEntropy` 包装器，但共用这把锁；无线断开或锁忙时不会使用不安全随机数，也不会让计数线程等待网络操作。

同步调度器现在把随机源的**可重试**失败和永久故障区分开：锁忙或无线暂时离线时稍后重试，而不是永久停机；此期间原绑定的按键仍归原生产单，待上传清空后才能切换。不可重试的随机错误仍安全停机。主机测试覆盖互斥并发、重试节流、离线期间计数归属及 FreeRTOS 模拟锁。

这些是独立组件，尚未创建实际设备任务。生产主程序必须确保所有 Wi-Fi 启停都经过同一锁、网络请求与无线重置由同一网络任务串行、每个任务独占自己的随机包装器，并检查锁创建成功。实际双核调度、Wi-Fi 回调和掉电行为仍需真机验证。

## 网络任务协调组件（模拟与本地联测）

`NetworkTaskCoordinator.h` 在单个网络任务中串行协调 Wi-Fi 策略、可信时间刷新和同步 RPC：离线或时间不可用时将待处理命令报告为失败，不确认计数；刷新失败按间隔重试。已执行但暂时无法放入结果队列的回复会原样保留，不会因断网而被替换或重复执行。Wi-Fi 锁忙时不改变网络状态，也不取走新命令。`AuthenticatedNetworkTime.h` 将时间证明和时间窗口接入该调度。

主机测试覆盖断网、时间刷新失败、计数线程在网络等待期间继续计数、结果队列拥堵及计时回绕；本地 TLS 测试串联协调器、时间证明、可信时间窗口和模拟 RPC。**这些仍不是实际设备任务或生产联通。** 调用方必须创建独立任务、提供可用的计数存储、专用凭据与生产 CA，并在真机验证网络超时、NVS 延迟和 2 秒冻结续约；时间刷新或网络长时间阻塞可能导致续约过期，此时应安全禁止确认，不应假定可立即识别断网。

## 固件、本地 HTTPS 与隔离数据库端到端联测

`tests/database/firmware-https-integration.mjs` 使用临时 CA 和本地 HTTPS 服务，把固件计数、网络协调、签名时间证明及真实 SQL 函数串起来；GPIO、Wi-Fi、存储和时钟仍是模拟。测试覆盖断网按键、离线期间禁止确认、网页改绑、旧计数留在原生产单、上传成功但回复丢失后的幂等重试、手动计数独立、冻结误按取消以及确认封顶。所有凭据与证书仅为临时测试数据，未连接正式 Supabase。

设置 `MBEDTLS_DIR` 和 `ARDUINOJSON_INCLUDE` 后可运行该脚本；GitHub 工作流使用禁用 mbedTLS 内置日期检查的配置重复此测试。该联测不证明 ESP32 硬件、真实 NVS 掉电、无线时延或正式数据库并发行为，也不代表可直接烧录生产。

# ESP32-S3 按键计数开发中

`include/ButtonCounter.h` 是已单独测试的按键去抖与长按计数核心，不是完整固件，不能直接烧录使用。按键连接 GPIO 4 和 GND，最终固件将使用内部上拉。按下稳定 25 ms 后加 1；保持 500 ms 后每 100 ms 加 1，释放期间不会继续重复计数。网络通信、设备配对、断网队列、确认同步握手和网页集成尚未实现；请勿将这个文件作为完整生产代码使用。

主机环境测试：`g++ -std=c++17 -Wall -Wextra -Werror tests/button_counter.cpp -o /tmp/xingyi-button-test && /tmp/xingyi-button-test`。实际开发板接线、长按、断网与断电行为尚未验证。

## 已确认的需求（后续实现前仍需验证）

- ESP32-S3-N16R8、GPIO 4 接按键另一端接 GND；2.4 GHz Wi-Fi，凭据仅在用户本地配置。
- 暂时一台设备，通过网页选择生产单；离线计数归属于发生时的原生产单，即使稍后改绑也不可转移。
- 网页手动输入维持独立，设备计数作为共享数单独显示并单独确认；设备计数确认按生产总数封顶，超出部分清空。
- 网络正常时目标 1 秒内显示；断网需要本地持久队列，目标支持至少一天（按最长 8 小时、每秒 10 次估算）。容量耗尽必须停止接受并提示。断电保存尽力而为，接受极短写入窗口丢数风险。
- 设备离线或存在未同步计数时禁止确认；确认需要同步握手并提示操作人员暂停按键。必须设计实际暂停/确认竞争的安全行为，不能仅用心跳猜测已同步。
- 下载页为独立网址。正式网页和现有数据库不能在无迁移、回归与多端测试的情况下直接改动。

## 离线存储组件（仍在开发中）

`DurableCounter.h` 定义了绑定版本、计数累计值和已确认值；存储层使用两个独立快照、校验和及递增版本。重传时携带累计值的设计可以支持服务端幂等处理，但服务端协议尚未实现。存在未同步计数时组件拒绝改绑；写入或读取校验失败时停止接受计数，不能静默清零。`PreferencesCounterStorage.h` 是 Arduino Preferences/NVS 适配器，目前仅用主机模拟接口测试过，**尚未使用 PlatformIO 实际编译、也未在开发板上验证**。

测试命令：`./tests/run-firmware-tests.sh`。此测试覆盖去抖、长按、计数重启恢复、重复确认、错误绑定、模拟存储故障和模拟 Preferences 接口；不证明断电原子性、闪存寿命、一天离线容量、网络交互或硬件兼容性。10 次/秒高频写入可能明显加快闪存磨损，完整方案必须经实际断电及耐久测试，必要时需要优化写入策略或增加硬件。

`tests/esp32_compile` 是专门的 PlatformIO **仅编译检查**，使用 `esp32-s3-devkitc-1`、16 MB Flash 和 QIO/OPI 内存配置编译当前组件，不能当作功能完整的固件烧录。该检查由 PR 中独立的 GitHub Actions 执行；本地如果有 PlatformIO，也可执行 `pio run --project-dir tests/esp32_compile`。编译成功只验证接口和工具链兼容，不能替代实板测试。

## 尚未部署的服务端接收基础

`supabase/migrations/202610290001_device_ingest.sql` 是独立新增的设备接收基础，不替换 PR1 表、权限或手动确认函数，也**尚未应用到线上**。它实现管理员创建设备及撤销、单设备随机密钥、绑定请求、累计值幂等接收以及独立设备草稿；旧绑定仍保留，以便离线数据归到原生产单。密钥只生成时返回，固件配置和安全配对页面尚未实现，不能用于实际设备。

后续 `202610290002_device_confirmation.sql` 新增了未部署的服务端冻结、两秒租约和原子确认基础，协议及限制见 `CONFIRMATION.md`。设备端冻结/排空握手、断电后的跨批恢复、生产单删除/归档时的处理、Realtime 推送、真实并发安全和速率限制等仍未实现；在这些内容以及真实 Supabase 与实板测试完成前，不可将迁移部署到生产。`tests/database` 使用完全隔离的 PGlite 测试迁移和 PR1 手动封顶；它不是 Supabase 并发或断网测试。

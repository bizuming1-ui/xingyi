# iPhone 热点优化候选（仅隔离测试，不可投产）

- ESP32 STA 启动后通过 ESP-IDF 尝试关闭 modem sleep 并读取配置，失败不阻断连接、计数、离线补传和冻结确认。它可能增加功耗和发热；驱动读取值不证明实际时延改善。
- 设备 HTTP、2 秒租约、可信时间和 TLS 的安全条件没有改动。外网、蜂窝链路和热点不能保证持续可用。
- 隔离站的设备 draft 视图使用 Postgres Changes 提示触发经授权的重新读取，事件不直接更新计数；原 250ms 单请求串行轮询与错误退避保留。收到提示时重读，飞行中提示合并成随后一次重读；停止或更换订单时屏蔽旧结果。
- 不更改正式项目和现有 RLS，不将消息视为设备在线、同步或可确认的证明。Realtime 提示可能丢失、延迟或被权限拒绝；轮询和读取仍是权威。
- 截至开发时，只读检查发现隔离项目 `device_order_drafts` 不在 `supabase_realtime` publication；因此推送尚未启用，仍依靠原轮询。不能在未验证操作员/非操作员 RLS、事件过滤、网络断线、恢复及消息配额之前添加 publication 或声称加速已生效。
- 上线前须核对 Supabase 项目方案和实时消息额度、蜂窝网络流量；比较无推送和启用推送的延迟、请求数、p95、错误率；按用户授权在隔离项目部署与回滚。不得直接修改正式项目或对真实订单注入故障。
- 接口日志中的上传成功不等于网页已经渲染；串口到首个浏览器帧的近似指标不等于物理按键端到端延迟。保留现有串口测速假设与局限。
